# Playing with friends

Two ways, depending on where your friends are.

## On your own network

1. **Settings → Multiplayer**, turn on **Allow LAN connections**.
2. **Restart server** — the engine reads that setting when it starts.
3. Copy **Your link — on this network** and send it over.

They paste it into the app's *Join a friend* box, or open it in a browser.
Joining runs nothing locally, so it starts in seconds.

## Over the internet

The app opens a Cloudflare tunnel from your machine outward. **No ports are
forwarded and nothing on your network is exposed** — the tunnel carries only the
game, and only to people holding a current invitation.

You can try this **without a Cloudflare account**. The catch is that the link
changes every time sharing restarts; for a link that stays the same, see
[A link that stays the same](#a-link-that-stays-the-same) below.

Keep the app open and the computer awake while people are playing.

### 1. Host a server, and turn on internet sharing

In **Settings → Multiplayer**, set **Mode** to **Host a server**, then tick
**Set up sharing over the internet (non-LAN)**. The checkbox only reveals the
controls below it; it changes nothing on its own.

<img src={hostAndInternet} alt="Multiplayer settings: Mode set to Host a server, and the Set up sharing over the internet (non-LAN) checkbox" />

### 2. Prepare the server and check the safeguards

Under **Internet sharing**, press **Prepare server for friends**, then **Check
internet account safeguards**.

Preparing secures the server's internal passwords. It backs up the database
first, keeps every account and character, and restarts the game services once.

The check will most likely say **Needs attention** for a GM/admin account. That
is the built-in `ragnarok` account: its password is also `ragnarok`, which is
printed in the README and all over the internet, so anyone could log in as your
GM. Fix it in the next step — you keep the account and its GM powers.

<img src={safeguardsNeedAttention} alt="Internet sharing: the safeguard check reports Needs attention for one GM/admin account with a weak or default password" />

### 3. Change the GM account's password

Open the **Accounts** tab and press **Refresh accounts** — the list stays empty
until you do.

<img src={refreshAccounts} alt="Accounts tab before refreshing: the Account dropdown is empty next to the Refresh accounts button" />

Choose **ragnarok** in the **Account** dropdown, type a new password twice, and
press **Change GM/admin password**. It needs **8–23** letters, numbers, spaces
or punctuation, and cannot be the account name.

This is now the password you log in with as `ragnarok`, so keep it somewhere.

<img src={changeGmPassword} alt="Accounts tab with the ragnarok account selected and the message Account updated in renewal. Log in again." />

Renewal and Pre-Renewal keep separate accounts. Change the password in the era
you are going to share.

### 4. Check again: all three should pass

Back in **Multiplayer**, press **Check internet account safeguards** again.
All three lines should say **Passed**.

<img src={safeguardsPassed} alt="Internet sharing: all three safeguard checks passed" />

### 5. Share with friends

Press **Share with friends**. It takes a little while — the first time, it
downloads Cloudflare's tunnel helper, and it restarts the game services once.

<img src={shareWithFriends} alt="Play together over the internet panel with the Share with friends button" />

It also unticks **Allow LAN connections**. That is on purpose: while sharing,
the invitation is the only way in, so the game stops listening on your local
network. Turn it back on when you are done sharing.

When it is ready, the status line says **Sharing is on** and **Copy invitation
link** becomes available.

<img src={sharingIsOn} alt="Status: Sharing is on. Send an invitation link to your friends." />

### 6. Send the link

Either press **Copy invitation link**, or click **Your link — over the
internet** at the top of the Multiplayer section. Both copy the whole link. It
looks like this:

```
https://some-random-words.trycloudflare.com/#invite=Xk3v9QpL2mR7tWz1...
```

Send all of it. The part after `#invite=` is what lets your friend in, so a link
cut off partway through will not work — and anyone you give it to can join.

### 7. What your friend sees

They open the link in any browser; they do not install anything. The
invitation page lets them either **Play with my game account**, which goes to
the normal login screen, or create an account first under **First time on this
server? Create a game account**.

<img src={invitationPage} alt="The invitation page a friend sees: Play with my game account, or create a game account" />

Once they have an account, they log in and make a character like on any server.

### Temporary links change every time

Without a Cloudflare account you get a **Quick Tunnel**, and Cloudflare hands
out a new `trycloudflare.com` address on every start. A crash, a restart or a
Repair therefore means sending a new link.

Quick Tunnels are meant for testing: no uptime guarantee, and at most **200
requests in flight at once**. Busy asset loading can reach that.

### A link that stays the same

Connect a Cloudflare account and use your own domain. You need a free account, a
domain on it, and an **API token** with:

| Permission | Scope |
|---|---|
| **Zone → Zone → Read** | your domain |
| **Zone → DNS → Edit** | your domain |
| **Account → Cloudflare Tunnel → Edit** | the account owning it |

Create it under **My Profile → API Tokens → Create Token → Create Custom
Token**. It is used only during setup; the tunnel credential then lives in your
operating system's secure password store.

Pick a hostname you are **not** already using — setup refuses to overwrite an
existing DNS record rather than replacing a site you have.

With a named tunnel the address is stable, and the invitation is kept across
restarts, so the whole link keeps working until you replace it.

## Controlling access

**Create a new link** replaces the invitation. The old link stops working
immediately and anyone using it is disconnected — that is what to reach for if a
link ends up somewhere public.

**Stop sharing** does the same and closes the tunnel, without stopping your own
game.

**Invitation lasts** sets an expiry in days, or 0 for none. Replacing is the
real control; expiry is a weaker version of it.

## What friends can and cannot do

They get an ordinary player account. They do not get GM commands unless you have
installed a mod that grants commands to everyone — **player-commands** does
exactly that, and it applies to invited friends too.

Failed logins are rate-limited per account and per browser, so one friend
mistyping a password cannot lock out the group.

## If it will not start

The reason appears in red under the buttons. `sharing.log` in the data folder
(**Settings → Save data → Open data folder**) has the full story, including the
Cloudflare helper's download and cloudflared's own output, and **Copy
diagnostics** includes its tail.
